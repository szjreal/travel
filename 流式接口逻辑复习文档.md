## 一、总览：一张时序图看全貌

```
用户点「发送」
  │
  ▼ ① 前端 Chat.vue：打包请求体
  ├── { message: "北京去哪玩", history: [{role,content}...] }
  │
  ▼ ② request.js fetch：POST 到后端
  ├── body: JSON.stringify(上面的对象)
  ├── Header: Content-Type: application/json
  │
  ▼ ③ 后端 express.json() 中间件解析
  ├── req.body = { message, history }  ← 自动解析成 JS 对象
  │
  ▼ ④ travel.js：创建 SSE 流式响应通道
  ├── res.setHeader('Content-Type','text/event-stream')
  ├── stream.send(data) 可以随时写数据
  │
  ▼ ⑤ travelService.chat()：组装消息 + 调大模型
  ├── messages = [SystemMessage, ...历史对话转成的消息, HumanMessage(本次提问)]
  ├── this.llm.stream(messages) → 返回一个"异步迭代器"
  │
  ▼ ⑥ for await 循环：大模型一块块吐字
  ├── chunk = { content: "北" }  ← 大模型返回的 AIMessageChunk
  ├── streamCallback(content)    ← 回调给路由层
  │
  ▼ ⑦ travel.js：包成 {type:'chunk', content} 写入 SSE
  ├── res.write('data: {"type":"chunk","content":"北"}\n\n')
  │
  ▼ ⑧ request.js reader.read()：前端收到二进制
  ├── value = Uint8Array(二进制)
  ├── chunk = decoder.decode(value)  →  字符串
  ├── lines.split('\n')              →  行数组
  ├── JSON.parse(去data:前缀)        →  { type:'chunk', content:'北' }
  │
  ▼ ⑨ Chat.vue onChunk 回调：渲染到页面
  ├── fullResponse += "北"
  ├── lastMsg.content = fullResponse ← 实时更新气泡文字
  │
  ▼ ⑩ 大模型结束 → stream.end()
  └── 前端收到 {done:true} → onComplete → isStreaming=false
```

### 数据5：`stream` — 大模型的流式迭代器

- **来源**：`travelService.js:231` → `const stream = await this.llm.stream(messages)`

- 这不是数组，是一个**异步迭代器**，可以 `for await...of` 循环遍历

- 大模型每算完一个字/词，就往里扔一块数据

#### this.llm 是什么？

`travelService.js:52`：

```js
this.llm = new ChatOpenAI({
    configuration: { baseURL: baseUrl },
    apiKey: apiKey,
    modelName: model,
    temperature: 0.7,
    streaming: true    // ← 开启流式模式
});
```

- `ChatOpenAI` 从 `@langchain/openai` 包 import 进来的一个**类**

- `new ChatOpenAI(...)` 创建了一个**实例对象**

- `.stream()` 是 LangChain 库**自带的方法**，从父类 `BaseChatModel` 继承而来

#### .stream(messages) 内部做了什么？

| 步骤 | LangChain 内部干的事                       |
| -- | ------------------------------------- |
| ①  | 把 messages 转成大模型 API 要求的 JSON 格式      |
| ②  | 用 fetch 向 baseURL 发 HTTP 请求，开启 SSE 流式 |
| ③  | 持续读取供应商服务器返回的流式数据                     |
| ④  | 把每个 token 包装成 `AIMessageChunk` 对象     |
| ⑤  | 返回一个 AsyncIterable（异步迭代器）             |

### 数据6：`chunk` — 大模型吐出的每一块字

- **来源**：`travelService.js:235` → `for await (const chunk of stream)`

```js
// chunk 的实际长相（第1块）
{ content: "北", response_metadata:{...} }

// 第2块
{ content: "京" }
// 第3块
{ content: "故" }
// ...
```

> **重要**：`chunk` 不是完整的一句话！是大模型**边算边吐的碎片**，可能是单字，也可能是一个词。

### 数据7-8：回调函数传递链路（重点！）

这个过程的本质是：**travel.js 把一个「处理函数」当参数传给 travelService，travelService 拿到大模型的字以后，再反过来调用这个函数**（这就是回调）。

#### 第1层：travel.js — 定义回调函数，当参数传出去

`travel.js:68-72`：

```js
const result = await travelService.chat(
    message,           // 第1个参数：本次提问
    history,           // 第2个参数：历史对话数组
    (chunk) => {       // 第3个参数：一个匿名函数，当作参数传进 chat() 方法里
        stream.send({ type: 'chunk', content: chunk });
    }
    // ↑ 这个函数现在不执行，只是"先交给你，等拿到字了再帮我调"
);
```

- `(chunk) => {...}` 这个函数**现在不会立即执行**

- 它被当作一个「值」塞进了 `travelService.chat()` 的第3个形参 `streamCallback`

#### 第2层：travelService.chat() — 接住回调函数，存进 streamCallback

`travelService.js:205-247`：

```js
// 第3个形参 streamCallback 就是【第1层】传进来的那个匿名函数
async chat(message, history, streamCallback) {
    // ...组装messages...
    const stream = await this.llm.stream(messages);
    let fullResponse = '';

    // 这里的 chunk 是大模型迭代器吐出来的【LangChain AIMessageChunk 对象】
    for await (const chunk of stream) {
        // chunk = { content: "北", ...其他LangChain内部字段 }
        const content = chunk.content || '';   // content = "北" （纯字符串）

        if (content.trim() === '') continue;
        fullResponse += content;

        // 关键！！这里反过来调用 travel.js 传进来的那个匿名函数
        // 把 "北" 这个纯字符串塞进去
        if (streamCallback) {
            streamCallback(content);  // ← 等价于执行第1层的匿名函数，此时参数 chunk = "北"
        }
    }
}
```

#### 两个同名的 chunk，不是一回事！

| 位置                                             | 变量名       | 类型               | 内容示例                                        |
| ---------------------------------------------- | --------- | ---------------- | ------------------------------------------- |
| `for await (const chunk of stream)` 里的 `chunk` | 大模型吐的原始对象 | `AIMessageChunk` | `{ content: "北", response_metadata:{...} }` |
| 第1层匿名函数 `(chunk) => {...}` 里的 `chunk`          | 传参过来的纯文字  | `string`         | `"北"`                                       |

> 中间经过了一步 `streamCallback(chunk.content)` —— **把对象的 content 字段取出来，变成纯字符串，再传回去**。

#### 第3层：回到 travel.js 匿名函数 — 包成 {type, content}

```js
// 此时 chunk 是 travelService 传过来的 content，也就是纯字符串 "北"
(chunk) => {
    stream.send({ type: 'chunk', content: chunk });
    //           ↑ type 字段是项目自己约定的协议标记
    //                        ↑ content 就是大模型吐出的字 "北"
}
```

产生的中间对象：

```js
{ type: 'chunk', content: '北' }
```

#### 第4层：streamUtils.js — 再包一层 SSE 协议格式

`streamUtils.js:21-23`：

```js
send: (data) => {   // data = {type:'chunk', content:'北'}
    res.write(`data: ${JSON.stringify(data)}\n\n`);
    // 实际写入网络的字符串 = 'data: {"type":"chunk","content":"北"}\n\n'
}
```

#### SSE 最终写入示例（后端往网络里实际写的字符串）

```
data: {"type":"chunk","content":"北"}\n\n
data: {"type":"chunk","content":"京"}\n\n
data: {"type":"chunk","content":"故宫"}\n\n
...
data: {"type":"complete","data":{"success":true}}\n\n
data: end\n
data:{"done":"true"}\n\n
```

#### 链路图

```
travel.js 第1层
─────────────────────────────────────────────────────────
  travelService.chat(message, history,
    (chunk) => { stream.send({type:'chunk', content:chunk}) }
     ↑                                             ↑
     │  把这个匿名函数交给第2层保管                此时chunk是纯字符串
     └──────────────────┐                         content="北"
                        │ 作为 streamCallback 参数传递
                        ▼
travelService 第2层
─────────────────────────────────────────────────────────
  async chat(message, history, streamCallback) {

    for await (const chunk of stream) {   ← 这个chunk是大模型对象
                    ↑                     // {content:"北", ...}
                    │ 这是迭代器自己的chunk，和第1层的chunk重名了但不是一个东西

      const content = chunk.content  // 取出 "北"（纯字符串）

      streamCallback(content)        // 调用第1层传进来的函数，把"北"塞进去
            │
            └──────────────────────────┐
                                       ▼
  回到 travel.js 第1层的匿名函数
─────────────────────────────────────────────────────────
  (chunk) => {          // chunk 现在 = "北" (纯字符串)
      stream.send({ type: 'chunk', content: '北' })
                          │
                          ▼
  streamUtils 第4层
─────────────────────────────────────────────────────────
  res.write('data: {"type":"chunk","content":"北"}\n\n')
```

#### 为什么要用回调？（分层职责）

| 层               | 职责                                          |
| --------------- | ------------------------------------------- |
| `travelService` | 业务逻辑层：只管和大模型对话，**不应该知道** `res`（HTTP响应对象）的存在 |
| `travel.js`     | 路由层：负责 HTTP 相关的事，把业务层产生的数据打包成 HTTP 响应       |

> 通过回调函数：业务层只负责「告诉我你拿到字了」，路由层负责「拿到字以后怎么发给用户」。以后换个非 HTTP 的场景（比如 WebSocket），travelService 的代码一行都不用改。

## 四、阶段三：前端接收 + 渲染

### 调用方与被调用方的关系

```
┌────────────────────────────────────────────────────────────────────┐
│  Chat.vue: fetchAIResponse()  —  调用方（传回调进去）                │
│                                                                    │
│  传给 fetchStream() 的参数：                                         │
│    ① url      = 'chat'                                             │
│    ② data     = {message, history}   ← 请求体内容                    │
│    ③ onChunk  = (chunk)=>{ 渲染1个字 }    ← 回调A                  │
│    ④ onError  = (errorMsg)=>{ 显示错误 } ← 回调B                    │
│    ⑤ onComplete = ()=>{ 结束loading }   ← 回调C                    │
│    ⑥ onAbort  = (controller)=>{ 保存控制器 } ← 回调D               │
└────────────────────────────────────────────────────────────────────┘
                              │ 调用
                              ▼
┌────────────────────────────────────────────────────────────────────┐
│  request.js: fetchStream(url,data,onChunk,onError,onComplete,onAbort) │
│                                                                    │
│  被调用方。负责：                                                    │
│    1. 发 HTTP 请求，打开流通道                                         │
│    2. while(true) 一块块读二进制                                      │
│    3. 解码、拆行、解析 SSE 协议                                        │
│    4. 根据解析结果：                                                 │
│        拿到 chunk  → 调用 onChunk(chunk)     → 回到Chat.vue执行回调A    │
│        拿到 error  → 调用 onError(message)   → 回到Chat.vue执行回调B    │
│        拿到 done   → 调用 onComplete(data)    → 回到Chat.vue执行回调C    │
│        刚发请求    → 调用 onAbort(controller) → 回到Chat.vue执行回调D    │
└────────────────────────────────────────────────────────────────────┘
```

### 逐步推演：假设后端依次发5个分片

| 顺序  | 后端发的内容（网络上真实传输的字符串）                                                             |
| --- | ------------------------------------------------------------------------------- |
| 第1块 | `data: {"type":"chunk","content":"北"}\n\n`                                      |
| 第2块 | `data: {"type":"chunk","content":"京"}\n\n`                                      |
| 第3块 | `data: {"type":"chunk","content":"故"}\n\n`                                      |
| 第4块 | `data: {"type":"chunk","content":"宫"}\n\n`                                      |
| 第5块 | `data: {"type":"complete","data":{...}}\n\ndata: end\ndata:{"done":"true"}\n\n` |

### 第一步：Chat.vue 传入 4 个回调函数

`Chat.vue:144-197`：

```js
fetchStream(
  'chat',                                              // 参数1 url
  {message: userMsg, history},                          // 参数2 请求体

  // 参数3 onChunk —— 回调A：每次收到1个字就调这个
  (chunk) => {
    fullResponse += chunk                              // 累加到完整字符串
    const lastMsg = messages.value[messages.value.length - 1]  // 找到最后那个气泡
    if (lastMsg && lastMsg.role === 'ai') {
      lastMsg.content = fullResponse                   // 把气泡的文字替换成当前累加的
    }
    scrollToBottom()
  },

  // 参数4 onError —— 回调B：出错时调
  (errorMsg) => {
    const lastMsg = messages.value[messages.value.length - 1]
    if (lastMsg && lastMsg.role === 'ai') {
      lastMsg.content = `抱歉，ai发生错误：${errorMsg}`
    }
    isStreaming.value = false
  },

  // 参数5 onComplete —— 回调C：全部完成时调
  () => {
    isStreaming.value = false
    currentController.value = null
  },

  // 参数6 onAbort —— 回调D：请求刚发出、拿到controller时就调（只调1次）
  (controller) => {
    currentController.value = controller                // 保存起来，给"停止生成"按钮用
  }
)
```

**进入 fetchStream 之前**，Chat.vue 的状态：

```js
messages.value = [
  { id:1001, role:'user', content:'北京必去景点', timestamp:'...' },  // 用户发的
  { id:1002, role:'ai',   content:'',            timestamp:'...' }   // 空占位气泡，等着填字
]
isStreaming.value = true
fullResponse = ''   // 局部变量
```

### 第二步：进入 request.js fetchStream —— 发请求 + 读流

`request.js:54-95`

#### 2.1 刚进入函数

```js
const controller = new AbortController()  // 创建一个可中止请求的控制器

if (onAbort) {                  // onAbort 就是 Chat.vue 传的第6个参数
    onAbort(controller)         // 【立即调用回调D】把 controller 交给 Chat.vue 保存
}                               // → Chat.vue 里 currentController.value = 这个controller
```

#### 2.2 发请求

```js
const response = await fetch('http://127.0.0.1:3300/api/travel/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({message:'北京必去景点', history:[...]}),
    signal: controller.signal   // 绑定中止信号
})
```

HTTP 请求发出，网络连接打开，服务器开始流式回复。

#### 2.3 拿到"读流器"

```js
const reader = response.body.getReader()   // 读流器，像"水龙头"，数据一到就能接
const decoder = new TextDecoder()          // 解码器，把字节数组转成字符串
```

#### 2.4 进入死循环读数据

```js
while(true) {
    const {done, value} = await reader.read()   // 卡在这里等数据！
    // ↑ 这行会"阻塞"，直到后端发了新数据或者连接断了才返回
    if (done) break
    // ... 处理 value
}
```

> `reader.read()` 是**异步等待**的。没数据时就停在这一行不动。后端一发来数据，马上醒来继续跑。

### 第三步：第1块数据到达「北」

#### 3.1 reader.read() 醒来了

```js
const {done, value} = await reader.read()
// done  = false   (还没完)
// value = Uint8Array([100, 97, 116, 97, 58, 32, 123, ...])
//         ↑ 这就是那串字符串的 UTF-8 字节码（二进制）
```

#### 3.2 解码成字符串

```js
const chunk = decoder.decode(value, {stream:true})
// chunk = 'data: {"type":"chunk","content":"北"}\n\n'
//         ↑ 二进制变成了人能看懂的字符串（SSE格式）
```

#### 3.3 按换行拆成多行

```js
const lines = chunk.split('\n').filter(line => line.trim())
// 原始 split 结果：
// ['data: {"type":"chunk","content":"北"}', '', '']
//                       ↑ 两个 \n 产生了两个空字符串
// filter(line=>line.trim()) 去掉空行，得到：
// lines = ['data: {"type":"chunk","content":"北"}']
```

#### 3.4 for-of 遍历每一行

```js
for (const line of lines) {
    // line = 'data: {"type":"chunk","content":"北"}'

    if (line.trim() === 'data: end' || line.trim() === 'end') continue
    // 不是 end，继续

    const jsonstr = line.replace(/^data:\s*/, '').trim()
    // 正则 /^data:\s*/ 意思：把行首的 "data:" 加上后面的空格都删掉
    // jsonstr = '{"type":"chunk","content":"北"}'

    const jsonData = JSON.parse(jsonstr)
    // jsonData = { type: "chunk", content: "北" }
    //            ↑ 变成了真正的 JS 对象！

    // 【根据 type 分发】
    if (jsonData.type === 'chunk') {
        onChunk(jsonData.content)
        // 调用回调A！！参数是 "北"
        // → 现在会跳回 Chat.vue 的 (chunk)=>{...} 那段代码执行
    }
    else if (jsonData.done) { ... }
    else if (jsonData.type === 'error') { ... }
}
```

### 第四步：跳回 Chat.vue 执行 onChunk 回调（渲染"北"）

`Chat.vue:169-176`：

```js
// chunk 参数 = "北"
(chunk) => {
    fullResponse += chunk
    // fullResponse = "" + "北" = "北"

    const lastMsg = messages.value[messages.value.length - 1]
    // 取到的是之前 push 的空占位气泡
    // lastMsg = { id:1002, role:'ai', content:'', timestamp:'...' }

        lastMsg.content = fullResponse
        // ↓↓↓ Vue 的响应式魔法 ↓↓↓

        // Vue 检测到对象属性变了 → 自动触发 ChatBubble 组件重新渲染
        // → 屏幕上那个空气泡里立刻出现一个 "北" 字 ✨

}
```

**此刻屏幕上用户看到的效果**：

```

AI气泡：  北_      ← 气泡里出现一个"北"字，后面像打字机一样
```

### 第五步\~第六步：第2、3、4块数据到达

完全一样的循环：

### 第七步：流结束信号到达（complete + done）

后端发了：

```
data: {"type":"complete","data":{"success":true}}\n\n
data: end\n
data:{"done":"true"}\n\n
```

#### 7.1 二进制解码

```js
chunk = decoder.decode(value)
// chunk = 'data: {"type":"complete","data":{...}}\n\ndata: end\ndata:{"done":"true"}\n\n'

lines = chunk.split('\n').filter(line => line.trim())
// lines = [
//   'data: {"type":"complete","data":{...}}',
//   'data: end',
//   'data:{"done":"true"}'
// ]
```

#### 7.2 遍历每一行

**第1行** `'data: {"type":"complete",...}'`：

```js
jsonData = { type: "complete", data: {success:true} }
// request.js 判断：
if (jsonData.type === 'chunk') ...      // 不匹配
else if (jsonData.done) ...             // jsonData.done 是 undefined，不匹配
else if (jsonData.type === 'error') ... // 不匹配
// → 这行实际上没触发任何回调
//   （travel.js 发的 type 是 'complete'，但 request.js 没判断这个 type）
```

**第2行** `'data: end'`：

```js
if (line.trim() === 'data: end') continue  // 直接跳过
```

**第3行** `'data:{"done":"true"}'`：

```js
jsonstr = line.replace(/^data:\s*/, '').trim()
// jsonstr = '{"done":"true"}'

jsonData = JSON.parse(jsonstr)
// jsonData = { done: "true" }   ← 字符串"true"，但 truthy 值即可

else if (jsonData.done) {         // "true" 字符串是 truthy，进入
    onComplete(jsonData.data)     // 调用回调C！
}
```

#### 7.3 跳回 Chat.vue 的 onComplete

`Chat.vue:189-193`：

```js
() => {
    isStreaming.value = false       // 关闭"正在生成"状态
    currentController.value = null  // 清空控制器
    scrollToBottom()
}
```

**此刻屏幕上**：loading 动画消失、「AI正在生成...」提示消失、输入框恢复可用

### 第八步：循环退出

```js
const {done, value} = await reader.read()
// 这次 done = true！因为 stream.end() 把连接关了
if (done) break   // 退出死循环
```

函数结束，整个流式流程完成 ✅
